# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `console` command to show the editor log messages a `Logger` registered with `OS.add_logger` captured since the plugin loaded, without changing the scene and without requiring an edited scene. `--tail` (default 100, max 1000) keeps only the last N matching messages, `--level` (default `all`) keeps one of `info`, `warning`, `error`, `script` or `shader`, `--since` (default 0) keeps messages with a sequence number greater than that cursor, and `--clear` empties the buffer after the reply is built. Each message carries `seq` (ascending from 1, never restarted), `level`, `text` and `truncated`; the reply carries `messages`, `count`, `dropped` (messages evicted from the full buffer) and `next_since` (the cursor for the next call). The buffer holds at most 1000 messages; each text is cut to at most 4096 bytes of valid UTF-8 with `truncated` true, and ASCII control characters are dropped so the reply stays valid JSON. `print` maps to `info`, `printerr` and `push_error` to `error`, `push_warning` to `warning`, a GDScript runtime error to `script`, and a shader compile error to `shader`. The logger callbacks can arrive from any thread, so the buffer is protected by a `Mutex`; the logger is registered when the plugin loads and removed with `OS.remove_logger` when it unloads. Not covered: messages logged before the plugin loaded, the editor Output panel history, and the output of the running game. The request is rejected before anything is read or cleared when the project path does not match, when an argument is missing or mistyped, or when the level is unknown.
- `list-resources` command to list the resource files the editor's file system view holds, as a bounded page, without loading or reading any resource and without changing the scene. `--path-prefix` keeps entries whose full path starts with a string, `--type` keeps entries whose engine class equals or inherits an engine class, `--limit` (default 100, max 1000) bounds the page, `--cursor` resumes after the last path of the previous page, and `--refresh` starts an editor file-system scan and waits for it to finish before printing the listing. An entry is `{"path","type"}`; a `GDScript` entry also carries `script_class` and `extends`. The list is in the editor's own walk order (a directory's files before its subdirectories, natural case-insensitive order inside a directory) and omits `TextFile` entries, unknown extensions, `.uid` and `.import` sidecars, any folder holding a `.gdignore`, and dot folders. The request is rejected before the file system is read when the project path does not match, when a filter has the wrong type, when `limit` is not an integer in 1..1000, when `type` is not an engine class in `ClassDB`, or when `path_prefix` or `cursor` does not start with `res://`; a `cursor` that is not in the tree is rejected with `cursor not found`. The reply is the scanning shape while a scan runs, so a listing is not a partial page.
- `inspect-resource` command to read one resource file's class and typed property values, using the same value codec and reply conventions as the other read commands, without changing the scene or writing any file and without requiring an edited scene. `--resource-path` must be a `res://` path; the plugin refuses, before anything is loaded, a path that does not start with `res://`, contains a `..` segment or `uid://`, names a scene (`.tscn`/`.scn`) or a script (`.gd`) file (case-insensitive, so `.TSCN`/`.SCN`/`.GD` too), is a text `.tres` over 4 MiB (`.TRES` too), or does not exist (TextFile, unknown extension, directory, missing file, dangling symlink). A resource whose dependency chain contains a `@tool` script is refused, naming that script, because `@tool` resource scripts run project code on load; the chain follows `get_dependencies` transitively and, for every `.gd` script reached, the `res://`, relative and `uid://` paths its source names in `preload("...")`/`load("...")` literals (multi-line and trailing-argument forms and a `uid://` literal resolved through the ResourceUID registry included) and the `extends` edge (`extends "path"`, a one-line `class_name Name extends ...`, an inner `class Name extends ...`, and `extends ClassName` resolved through the project's global class list), so a preloaded or base-reached `@tool` resource is caught even when the outer resource later fails to load; a path a script builds at run time, or a `uid://` the editor does not know, cannot be seen by the source scan. A script that merely mentions `@tool` in a comment or string, or inside a triple-quoted string, is accepted; a script that only `extends` a `@tool` script without `@tool` itself (path, one-line, or `class_name` form) is refused and the reply names the base script, because the walk follows the extends edge and the base is a `@tool` script. The load uses `ResourceLoader.CACHE_MODE_IGNORE_DEEP` only, so a live material an open scene holds is never overwritten. An embedded sub-resource (`file::id`) is shown inline with a depth limit of 3 and a loop guard; an external resource reference is shown as `{"path","type"}`; a null property is null; an array over 10,000 elements is replaced by `{"type","size","truncated":true}`; a corrupt, empty, or text-scene-named-`.res` file replies `resource failed to load`. The CLI resolves symlinks before sending and rejects a `res://` path that resolves outside the project.
- `set-parent` command to move one node of the currently edited scene under a new parent through the editor's `EditorUndoRedoManager` as a single Undo/Redo step, without saving the scene. `node_path` and the new `new_parent_path` are scene-relative; `--index` sets the node's final position among the new parent's children (default appends); `--keep-global-transform` (the default) preserves the full global transform of a `Node2D` and a `Node3D` and the global position only of a `Control`, while every other node type ignores it. The move changes only the position: every node of the moved subtree keeps exactly the owner it already had, so a node the edited scene saved before the move is still saved after it and Undo restores the owners exactly. The request is rejected before any change when the node is the scene root, has no owner, is inherited from a sub-scene, or is inherited from the edited scene's base scene (an instance root owned by the edited scene root is accepted and keeps its scene file); when the new parent is not the scene root or a node owned by it (including any node inside an instanced sub-scene's own internal structure; an inherited node is owned by the scene root and is accepted, the same way it is for `create-node`); when the new parent is inside the moved node's own subtree; when the move is a no-op (the same parent and the same final position); when the new parent already holds a child with the node's name (the engine's re-parent call would rename the node to an internal placeholder; this is the sibling-name rule `create-node` and `rename-node` use); and when `index` is not an integer or is outside the new parent's range. Exported `NodePath` values on other nodes are not rewritten. The project path is checked before the other fields, so a wrong project path is reported even when another field is malformed. Because the interface declares `keep_global_transform` as a boolean, the CLI's flag can only request true; a caller that wants false sends the raw request.
- `set-parent` now rejects a node inherited from the scene's base scene even when the derived scene overrides it with a property, a script, a group or a signal connection. The earlier check compared the node against the edited scene's own packed state, where an overridden inherited node is listed, so such a move was accepted and a save plus a fresh reload showed the subtree twice. The plugin now packs the edited scene and walks the chain of base states, treating the node as inherited when any level lists it; every level is visited, because an intermediate base can hold only the instance row. A node the derived scene owns itself stays movable under an inherited parent, a scene with no base scene rejects nothing extra, and the existing rejection message is unchanged.
- `eval` command to compile a submitted GDScript source, instantiate it, and call its `func run(editor, undo_redo)` entry on the live editor's main thread, returning the value, the captured errors and printed output, and whether the edited scene changed. `code` is the source (with or without `@tool`); `--timeout` (default 5000 when absent, an explicit null is refused, must be positive) is a best-effort millisecond budget that never interrupts the call. The project path is checked first, before `code` or `timeout`, and a rejected request changes nothing. A snippet that opens another scene reports `scene_changed` true but does not mark the newly opened scene unsaved, and a snippet that switches scenes is outside the dirty-marking guarantee; the oversized-value refusal claims unsaved only when the plugin actually marked in that request. `edits_scene` is true because a snippet may edit; the flag is informational and the CLI does not read it. The reply carries `value` (encoded with `JSON.from_native`, objects off; a value nested deeper than 100 tagged levels is refused with `value` null and `completed` false, the count being the nesting of the encoded value in JSON container levels, where an `Array` costs one and a `Dictionary` costs two and the container being examined is included, so a value of exactly 100 levels comes back exactly and one level more is refused; the count does not see the object and args array that the encoding adds for a tagged terminal value such as a `Vector2`, a packed array or a `Transform3D`, so such a value can reach up to 102 levels in the reply; the real command line reads about 125 levels, so the reply stays readable with a worst-case margin of 23 levels), `completed` (true only when the code compiled and `run` returned without a non-warning error during reload, construction or the call, including `_init` and an error raised while the reload initializes a `@tool` script; a warning keeps the value), `errors` (the `{file,line,function,message,type}` with `type` warning, error, script or shader a `Logger` installed around the call captures), `output` (the `print()` lines with spaces kept and control bytes other than tab, newline and carriage return dropped), `scene_changed`, `elapsed_msec`, and `timeout_exceeded`. An `Object` result and an encoding failure give `value` null and `completed` false; a `Callable` decodes to an empty invalid Callable and an `RID` to `RID(0)`, so none of the three is a usable value. A submitted script instance is freed after the call only when it is left parentless and outside the tree: a `RefCounted` frees itself, and a `Node` stays alive when it is inside the tree or when another `Node` is its parent. A value larger than 1 MiB is replaced by an error naming its size and saying the code ran. `eval` is the one command that may break rule 3 (a direct scene edit creates no undo entry) and rule 6 (the code can hold the main thread); it marks the scene unsaved only when a before/after fingerprint of the edited scene tree (path, class, owner, script, groups, connections, stored properties) differs in the same scene root, and it never saves. On a 203-node fixture the fingerprint took 39.608, 29.792, 18.240, 17.741 and 19.789 ms (mean 25.034), which does not reproduce the PLAN.md mean exactly.
- The replay baseline is extended to 825 rows: rows 1-764 stay byte-identical (recorded twice), and the new rows cover `inspect-resource`'s accepted typed reads (`.tres`, `.res`, `.gdshader`), the object-valued encodings, the 4 MiB `.tres` cap and array truncation, the `@tool` walk (top script, embedded sub-resource, external dependency, script preload, multi-line and extra-argument load literals, a `uid://` literal, the `extends` path, one-line `class_name`, inner-class and `class_name` edges including a two-level chain, malformed failed-to-load preload, comment and triple-quoted-string false positives, an `@icon`-prefixed extends, and the extends-a-`@tool` refusals that name the base), the case-insensitive extension guards, and every refusal with its exact message.
- The replay baseline is extended to 1172 rows: rows 1-825 stay byte-identical to the previous baseline (recorded twice), rows 826-827 publish the command interface with `console`, `set_parent` and `eval` appended as entries 18, 19 and 20, and the appended rows cover the console, set-parent and eval sessions described below.
- The console validation rows cover the project guard answering first, each mistyped or out-of-range argument and the unknown level, plus one successful read with a cursor past every message. A successful read of real messages is not recorded: the editor's startup log text varies by run, so it cannot be byte-deterministic; the happy path is proved by isolated-editor probes instead.
- The set-parent rows cover every accepted move (a plain node, a Node2D, a Node3D and a Control with the default keep-global-transform, an instanced sub-scene root, an explicit index, and a raw keep-global-transform false) and every rejection with an equal before/after file hash, the fresh reload of those moves (the moved subtree, its group, its signal connection and its unique name), set-parent in a scene derived from a base scene (a wrong project path answered before a malformed index, keep_global_transform, node_path or new_parent_path; a node inherited from the base scene and a node inside it rejected with an equal before/after file hash; a local node moved; and a local node moved under an inherited parent), and the fresh reload of the derived-scene moves.
- The base-inherited rename and delete rows cover the rejections of `rename-node` and `delete-node` (an inherited node with a property override, an inherited node with a property and script override, inherited descendants at two depths, the base scene's instanced sub-scene root, and a wrong project path answered first; each rejection is bracketed by identical `scene_tree` replies with an equal before/after file hash, and a refused `set-parent` of the same node shows that the rename-then-set-parent and delete-then-create-then-set-parent compositions cannot start) plus the fresh reload of an allowed local rename and an allowed local delete in a derived scene, which do not duplicate.
- The eval rows cover each returned value type, print output, a compile failure, a run-time failure and a request that blocks past a small timeout, the rejected requests (the project guard answering first, a bad timeout, a bad code field), a value the engine refuses to encode, the tagged depth boundary for an `Array`, a `Dictionary` and a mixed shape, an `Object` script instance freed (checked via editor meta on the next call), rich and spaced output, an explicit null timeout refused, a warning that keeps its value, a `push_error` that fails, an `_init` error that fails, three cases where an error raised while the reload initializes the submitted `@tool` script (a failing static initializer, a `_static_init` that calls `push_error`, and a preloaded `@tool` script with an error) each answered with `completed` false and `value` null and each followed by a clean call, and a `Node` that another `Node` parents kept alive across two calls. The harness asserts every recorded eval reply body parses as JSON. The elapsed milliseconds and the anonymous `gdscript://` error source path are normalised by the harness so the rows are byte-deterministic; neither is normalised on the wire.

### Changed

- The command-line tool is `godot-cli`, and the plugin's commands run through `call`: `godot-cli call rename-node Player Hero --project-path /path/to/project`. The command's own subcommands are `commands`, which lists what the running editor can do (`godot-cli commands`, or `godot-cli commands --json` for the schema verbatim), `--help` and `--version`. The plugin publishes the interface of every command (name, description, whether it needs a project path or edits the scene, and each argument's name, flag, positional index, type, required flag, default and help) and answers `{"command":"commands"}` with it and a protocol version; the CLI fetches that interface from the editor on every run, validates the invocation against it, and builds the request from it, so no command is hard-coded in the CLI and nothing is cached between runs. The request that reaches the plugin for a valid invocation is unchanged. Per-command help and the command list need a running editor.
- `tools/replay/README.txt` counts match the harness again: one `--import` plus thirty-eight editor launches and 1172 stored rows (1053 requests and 119 file checks), not twenty-eight launches and 967 requests.
- `docs/reference.md` records the measured cost of the base-scene detector that `set-parent`, `rename-node` and `delete-node` share: about 1.7 ms for a 201-node scene with no base, about 5.3 ms for a 201-node scene whose nodes come from a base scene, about 4.7 ms for 201 inherited nodes plus one local node, and about 6.7 ms for a 401-node edited scene with 200 local nodes under a 201-node base. The cost follows the number of serialized nodes and properties of the edited scene and whether the scene inherits from a base scene, and it is paid once per call of the three commands.

### Fixed

- `rename-node` rejects, before the undo action, a rename of a node inherited from the edited scene's base scene, with or without a local property, script, group or signal override. The node's owner is the edited scene root, so the earlier ownership check let it through and the engine wrote a local copy beside the inherited node; a save and a fresh reload then showed the subtree twice. The new check reuses `CommandSupport.node_is_inherited_from_base`, the same helper `set-parent` uses, and replies `node is inherited from the base scene and its rename would not be saved: <path>`. The scene root itself (the base instance) and a local node under an inherited parent still rename.
- `delete-node` rejects, before the undo action, a deletion of a node inherited from the edited scene's base scene, with or without a local override: its owner is the edited scene root, so the instance walk let it through, but the editor writes no removal for the inherited node, so the node returned on a fresh reload. The reply is `node is inherited from the base scene and its deletion would not be saved: <path>`. A local node under an inherited parent still deletes.
- `eval` no longer reports a run as completed when the submitted `@tool` script raised an error while `reload()` initialized it. The failure scan started after the reload, so a failing static initializer, a `_static_init` that calls `push_error`, and a preloaded `@tool` script that raises while loading each returned `completed` true with `value` `i:42` and the error listed. The count now starts before the reload, so those three reply `completed` false with `value` null and one `errors` entry. A warning raised during the reload still keeps `completed` true and the returned value, and a reload that fails outright still fails through its own branch.
- `eval` no longer accepts a value one or two levels past the limit it documents. The depth walk compared a container's depth before counting that container, so an `Array` at 100 levels was accepted and a `Dictionary` at 102 levels was accepted. The current container's own cost is now part of the comparison, so exactly 100 levels comes back exactly and one level more is refused, for an `Array`, a `Dictionary` and a mixed shape.
- `eval` no longer frees a submitted `Node` that another `Node` parents. The cleanup tested only whether the instance was inside the tree, so a snippet that handed ownership of `self` to a parent it kept alive lost the child while the parent was still valid. An instance with a parent is now preserved; an orphan `Node`, an orphan `Object` and a `Node` added to the tree and then removed are still freed, a `RefCounted` and a `Resource` are untouched, and a snippet that frees itself still produces the engine's own error with no double free.
## [0.6.0] - 2026-10-09

### Added

- `connect-signal` command to connect a signal on one node of the currently edited scene to a method on another node through the editor's `EditorUndoRedoManager` as a single Undo/Redo step, without saving the scene. The optional `--deferred` and `--one-shot` flags add `CONNECT_DEFERRED` and `CONNECT_ONE_SHOT` to the `CONNECT_PERSIST` flag the connection is always made with. The request is rejected before any change when a node, the signal, or the method is missing, when the connection already exists (including one a sub-scene defines), or when the source node is inside a non-editable instanced sub-scene (where the engine would silently drop it on save); a target inside a non-editable instance is accepted. An argument-count mismatch between the signal and the method is not checked and fails only when the signal is emitted.
- `set-group` command to add or remove one persistent group on a node of the currently edited scene through the editor's `EditorUndoRedoManager` as a single Undo/Redo step, without saving the scene. By default the group is added; the CLI's `--remove` flag removes it instead. The request is rejected before any change when the node is missing, the group name is empty, the group name contains U+FFFD (Godot's JSON parser turns an escaped NUL into U+FFFD, so the name cannot be told apart), an add targets a group the node is already in (locally or inherited), a removal targets a group that is not a persistent local group (an inherited group, a runtime group, or an engine-internal session group), a removal targets a node inside a nested instance whose origin cannot be read in one step, or the node is inside a non-editable instanced sub-scene (where the engine would silently drop the group on save); the instance root itself is accepted with Editable Children off.
- `set-unique-name` command to set or clear `Node.unique_name_in_owner` (the `%` name) on a node of the currently edited scene through the editor's `EditorUndoRedoManager` as a single Undo/Redo step, without saving the scene. By default the flag is set; the CLI's `--remove` flag clears it instead. The request is rejected before any change when the node is the scene root (`%Root` never resolves), the node is inside a non-editable instanced sub-scene (where the engine would silently drop the flag on save), an add targets a node that is already unique or would collide with another unique name in the same owner scope (the error names the claiming node), a removal targets a node that is not unique or whose flag is inherited from a sub-scene, or a removal targets a node inside a nested instance whose flag origin cannot be read in one step; the instance root itself is accepted with Editable Children off.
- `instantiate-scene` command to add an instance of a `PackedScene` under a node of the currently edited scene through the editor's `EditorUndoRedoManager` as a single Undo/Redo step, without saving the scene. `--scene-path` must be a `res://` `.tscn` or `.scn` file and `--parent-path` must be the scene root (`.`) or a node owned by it. No name is taken: the instance keeps the scene root's name, made unique by the engine on a sibling collision, and the reply reports the applied name. The request is rejected before any change when the scene path is not a string, does not start with `res://`, has a `..` segment, does not end with `.tscn` or `.scn`, does not exist, does not load as a `PackedScene`, or cannot be instantiated; when the scene depends on a missing resource; when the edited scene appears in the scene's dependency closure (a self, transitive or inheritance cycle); or when the parent is inside an instance's own internal structure or has no owner. Instantiating runs the scene's `@tool` scripts, so a rejected request instantiates nothing.

### Fixed

- `rename-node` rejects, before the undo action, a rename that would clear the target's unique name (`unique_name_in_owner`) because another unique node in the same owner scope holds the name the engine would apply. The check only reads the scene and never renames the live node, so a rejected request runs no callback. When no sibling of the target holds the requested name the exact name is tested; when a sibling holds it the check rejects a unique node whose name is the requested name without its trailing digits followed by digits, a conservative superset of the names the engine can apply (it can reject a rename the engine would allow). The claimant scan includes internal children and ignores a null owner (the scene root). A target without a unique flag is unaffected. A script or observer that renames the node during the real rename can still cause a collision this check cannot see; the README describes it.
- `rename-node` also rejects, before the undo action, a rename of a target that is neither the scene root nor owned by the edited scene root: the engine accepts its rename in the open editor, but the name is not kept after a save and a fresh reload, so such a rename would not persist. The rejected targets are instance-owned descendants of an instanced sub-scene, the roots of nested instances, and nodes with no owner. Instance roots owned by the edited scene, local nodes under an editable instance, and plain nodes are not affected by this check and rename and persist. The unique-name check described above runs first.

## [0.5.0] - 2026-10-01

### Added

- `open-scene` command to open a scene in the running editor by path, optionally saving a dirty edited scene first with `--save`; without `--save` a dirty edited scene stays open as a background tab. Only native scenes are opened; imported scenes are rejected before anything is saved. The reply names the scene actually edited after the open, so a scene the editor silently refuses to open is reported as an error, and lists the scenes that still have unsaved changes in `unsaved` (an untitled dirty scene appears as an empty string, e.g. `[""]`).
- `inspect-class` command to report an engine class's ClassDB reflection (ancestors, instantiability, Node ancestry, and declared properties, methods, and signals) without changing the scene and without requiring an edited scene.
- `query-nodes` command to search the edited scene's node tree for nodes matching a class, group, and glob name filter, in tree order, up to a bounded limit, without changing the scene.
- `inspect-node` command to read a node's class, child count, and the values of its editor-visible properties without changing the scene, including the JSON shape needed to feed a supported value back through `set-property`.

### Fixed

- Requests that arrive in several TCP segments are no longer cut short; the plugin buffers and assembles each request until its terminating newline.

### Changed

- A request that exceeds the 8 MiB cap without a terminating newline is rejected with an error naming the cap and the received size.
- A connection that sends only part of a request and then stalls is dropped after the 5 second idle timeout, and a request that omits the trailing newline is accepted after that timeout.
- A request of several megabytes is now handled whole, and it pauses the editor for roughly 0.2 to 0.5 seconds while it is validated and applied.

## [0.4.0] - 2026-09-29

### Added

- `set-property` now accepts all Packed*Array types and typed `Array[T]` properties, coercing each element with the same per-type rules and naming the element index in errors.
- Untyped `Array` properties and typed arrays of unsupported element types (Object, Node, Resource, Dictionary, nested Array, Variant) are rejected before any change.

### Changed

- The plugin's malformed-request error now reports how many bytes were received, so a request that exceeds the single-pass socket read is recognizable as too large.

## [0.3.0] - 2026-09-29

### Added

- `set-property` now accepts Vector2i, Vector3i, Vector4, Vector4i, Rect2, Rect2i, Transform2D, and Transform3D, all as plain JSON arrays.
- Int-vector and Rect2i components must be integral signed 32-bit integers; fractional or out-of-range components are rejected before any change.

## [0.2.0] - 2026-09-29

### Added

- `rename-node` command to rename a node in the currently edited scene via a single Undo/Redo step.
- `create-node` command to instantiate a built-in Node subclass as a child of a scene node via a single Undo/Redo step.
- `set-property` command to set a named property on a node in the currently edited scene, with strict type coercion for bool, int, float, String, StringName, NodePath, Vector2, Vector3, and Color.
- `delete-node` command to remove a node and its subtree from the currently edited scene via a single Undo/Redo step, with owner restoration on Undo.
- `save-scene` command to persist the currently edited scene to disk through EditorInterface.

### Changed

- `set-property` now rejects an int value for a PROPERTY_HINT_ENUM property unless it matches one of the declared enum values.

### Fixed

- `create-node` now rejects parents not owned by the edited scene root, preventing nodes that would silently vanish on save.
- Added `.uid` files to `.gitignore` to exclude Godot-generated sidecar files from the addon source.

## [0.1.0] - 2026-09-25

### Added

- Initial release of the Godot Pipeline CLI and editor plugin.
- `status` command to report the editor version, playing state, and active scene path.
- `scene-tree` command to report the node tree of the currently edited scene.
- GDScript EditorPlugin that communicates with the CLI over a loopback TCP socket.
