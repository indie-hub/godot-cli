# Unity CLI parity map

This page holds one row for each command of the Unity command line (`unity command`, `unity list`). It answers one question per command: can Godot Pipeline do the same thing? The earlier version of [`PLAN.md`](../PLAN.md) mapped a different Unity surface, an MCP server with 100 tools, and was wrong. Its table is removed and stays in git history.

The command list was taken on 2026-10-13 from a live Unity 6000.4.4f1 project. It holds 142 commands. Three rooms mapped them in chunks of 39, 50 and 53 commands, one room per chunk. Each chunk was then re-derived blind by a room from another vendor. 106 commands had the same class from both rooms, 14 differed only on how large the gap is, and 22 differed on facts. The 22 commands the rooms disagreed on were measured in a real Godot 4.7.2 editor: 10 by two rooms each and 12 by one room. `eval` has measurements from two vendors. `eval_file` has a measurement from one vendor. Every Godot class, method, signal and property named in the Godot mechanism column was checked by script against the Godot 4.8-dev engine documentation: 323 entries from the author rooms and 403 from the blind rooms, all resolved. The check proves that an API exists. It does not prove that the mapping is the right one. A row proposes scope. It does not promise that a command exists. Only the commands named in the column 'built Godot Pipeline command', and the entries marked built in the table of Godot-only capabilities, exist today.

## Legend

Each row carries one class and one evidence level.

### Classes

- `DIRECT`: a Godot equivalent with the same shape. The Unity command maps onto one Godot call or one built command.
- `ADAPT`: the same goal, but the Godot model differs. The row names the mechanism and the gap.
- `ADAPT (near-direct)`: two rooms disagreed only on the size of the gap. One room wrote `DIRECT` and the other wrote `ADAPT`, and the same mechanism was named. The row keeps the stricter class, `ADAPT`.
- `GODOT_NATIVE`: the Godot engine already does this with its own command line or a built-in workflow, so Godot Pipeline needs no command.
- `UNITY_ONLY`: the Unity command has no Godot equivalent, because the subsystem does not exist in Godot.

### Evidence levels

- **measured and replicated**: two rooms measured the Godot behavior in a Godot 4.7.2 editor and reached the same result.
- **measured, one vendor**: one room measured the Godot behavior in a Godot 4.7.2 editor.
- **docs and source only**: the row comes from the Godot 4.8-dev engine documentation and the engine source. No editor measurement backs it.

The evidence level describes the evidence for the mapping of the Unity command to Godot, not for the built Godot Pipeline command that covers it. A row can name a built command that was measured many times in a Godot 4.7.2 editor and still read `docs and source only`.
